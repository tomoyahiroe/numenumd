# numenumd

[English](README.md) | 日本語

numenumd は、ローカルの Markdown ファイルを Notion 風の WYSIWYG エディタで
編集できるようにする Chrome 拡張機能です。ディスク上の `.md` ファイルを Chrome で
開けば、その場で編集できます。サーバーもアカウントも不要で、何もアップロード
されません。保存すると、整形済みの Markdown を同じファイルへ書き戻します。
リッチテキストとして表示できない記法は、書かれたとおりのまま保たれます。

![numenumd で Markdown ファイルを編集している画面](docs/images/screenshot-2-blocks.png)

## インストール

numenumd は Chrome ウェブストアでは公開していません。リリース版またはソース
コードから、パッケージ化されていない拡張機能として読み込みます。

### リリース版から(Node.js 不要)

1. [Releases](https://github.com/tomoyahiroe/numenumd/releases) から
   `numenumd-vX.Y.Z.zip` をダウンロードして展開する。
2. `chrome://extensions` を開き、右上の **デベロッパー モード** を ON にする。
3. **パッケージ化されていない拡張機能を読み込む** をクリックし、展開したフォルダを選ぶ。
4. numenumd の **詳細** を開き、**ファイルの URL へのアクセスを許可する** を ON にする。
5. 任意の `.md` ファイルを Chrome で開く(タブへドラッグするか、`file://` の URL を開く)。

### ソースコードから

Node.js 22 と npm が必要です。

```bash
git clone https://github.com/tomoyahiroe/numenumd.git
cd numenumd
npm install
npm run build
```

その後、上の手順 2〜5 を行います。手順 3 では生成された `dist/` フォルダを
選びます。

**手順 4 が必要な理由:** numenumd は `file://` のページで動作しますが、Chrome は
既定で拡張機能がこれらのページで動くことを許可していません。**ファイルの URL へ
のアクセスを許可する** が OFF のままだと、`.md` ファイルはプレーンテキストの
まま表示されます。

## 機能

- **入力中の Markdown ショートカット**: 見出しは `# ` 〜 `###### `、リストと
  ToDo は `- `・`1. `・`[] ` / `[x] `、引用は `> `、コードブロックは ` ``` `、
  数式ブロックは `$$` の後に Enter。
- **スラッシュメニュー**: `/` を入力すると、見出し 1〜3、箇条書き・番号付き・
  ToDo リスト、引用、コードブロック、表、数式ブロックを挿入できます。続けて
  入力すると絞り込めます(英語のキーワードに加え、「見出し」「数式」などの
  日本語キーワードにも対応)。
- **数式**: インライン `$…$` とブロック `$$…$$` を KaTeX で描画します。数式
  ブロックはクリックで LaTeX を編集でき、`Escape` または `Cmd/Ctrl+Enter` で
  確定します。地の文の `$`(`$5 and $10` など)は数式と誤認しません。
- **表**(GFM パイプテーブル): `/table` で挿入、`Tab` でセルを移動(最後の
  セルでは行を追加)、`+` ボタンで行・列を追加、グリップから行・列を選択して
  `Backspace` で削除できます。列の揃え(`:---:` など)は保持されます。
- **Markdown を失わない**: 生 HTML、リンク参照定義、脚注定義など、エディタが
  リッチテキストとして表示できないものは生の Markdown ブロックとして表示し、
  変更せずに保存します。YAML frontmatter は折りたたみ可能なブロックで表示され、元のとおりに
  書き戻されます。
- **保存**: 最初の `Cmd/Ctrl+S` で保存ダイアログが開き(ファイル名は入力済み)、
  以降は無音で保存します。ファイルごとの保存先を記憶するため、タブをリロード
  しても選び直す必要はありません(Chrome が編集の許可を求めることがあります)。記憶するのは保存先だけで、本文は記憶せず、
  「⋯」メニューからいつでも消せます。エディタの外にフォーカスがあっても
  `Cmd/Ctrl+S` が効きます。
- **安全な保存**: 前回の保存以降に他のアプリがファイルを変更していた場合は、
  上書き前に確認します。未保存の変更があるタブを閉じようとすると警告が出て、
  未保存の間はタブのタイトルが `●` で始まります。
- **一貫した整形**: 保存したファイルは Prettier で整形され、変更せずに再保存
  しても同じ内容になります。
- **テーマ**: ヘッダのボタンで Auto(OS に追従)→ Light → Dark を切り替えます。
  選択は保存されず、タブごとに Auto から始まります。

## キーボードショートカット

macOS では `Cmd`、Windows と Linux では `Ctrl` です。

| ショートカット                                | 動作                         |
| --------------------------------------------- | ---------------------------- |
| `Cmd/Ctrl+S`                                  | 保存                         |
| `Cmd/Ctrl+B`                                  | 太字                         |
| `Cmd/Ctrl+I`                                  | 斜体                         |
| `Cmd/Ctrl+E`                                  | インラインコード             |
| `Cmd/Ctrl+Shift+X`(または `Cmd/Ctrl+Shift+S`) | 取り消し線                   |
| `Cmd/Ctrl+K`                                  | リンク(選択したテキストに)   |
| `Cmd/Ctrl+Alt+1` 〜 `Cmd/Ctrl+Alt+6`          | 見出し 1〜6                  |
| `/`                                           | スラッシュメニューを開く     |
| `Escape` または `Cmd/Ctrl+Enter`              | 数式ブロックの編集を確定する |

## 既知の制限

- エディタのメッセージとメニューは日本語(スラッシュメニューの項目は英語)。
- ToDo リストの項目で、チェックボックスと本文が別の行に表示される。
- インラインコード内の `$…$` が数式として描画される。表示だけの問題で、保存
  される Markdown は変わらない。
- 表のセル結合には対応していない。GFM のパイプテーブルにセル結合の記法が無い
  ため。`rowspan` / `colspan` を使った HTML の表は生の Markdown ブロックとして
  保たれる。
- 表のセルに書けるのは1行分のインラインのみ。セル内の改行・箇条書き・コード
  ブロックは、GFM のセルが表現できないため無効にしている。
- 表のセル内のコードスパンに含まれるパイプ(``| `a|b` |``)はセルを分割する。
  markdown-it がインラインコードの解析より前にセルを分割するため。その結果、
  ヘッダより多いセルを持つ行ができる場合は表全体が生の Markdown ブロックとして
  保たれる。そうでない場合は編集可能な表になり、保存時にバッククォートが
  エスケープされて(``\`a | b\` ``)記法が変わる。
- 参照リンク(`[text][ref]`)は保存時にインライン形式へ展開され、`[ref]: url` の
  定義行が使われないまま残る。表示は同じだが、記法は変わる。
- 地の文の角括弧は保存時にエスケープされる(`array[0]` → `array\[0\]`)。表示は
  同じで再読み込みしても安定しているが、ファイル上の文字は変わる。

## プライバシー

numenumd は何も収集せず、ネットワーク通信も行いません。保存するのは各ファイルの
保存先(ブラウザの IndexedDB 内)だけで、書いた内容は保存しません。他のローカル
ページから見えうるものも含め、詳しくは [PRIVACY.ja.md](PRIVACY.ja.md) を参照して
ください。
