# numenumd 設計ドキュメント

日付: 2026-08-01
ステータス: 承認待ち

## 概要

ローカルの Markdown ファイルを Notion ライクな WYSIWYG UI で編集できる Chrome 拡張機能。
`file:///…/*.md` をブラウザで開くと、そのページがエディタに置き換わる。保存時には
Markdown が Prettier で整形されて元ファイルに上書きされ、`.md` ファイル以外の永続状態は
一切持たない。

## 決定事項(経緯付き)

| 論点 | 決定 | 理由 |
|---|---|---|
| エディタの入口 | `file:///*.md` を開いたら拡張がページを乗っ取る | 「ファイルをブラウザで開く」動線に馴染む |
| ファイル書き戻し | File System Access API(初回保存時のみピッカー) | 拡張単体で完結。ネイティブヘルパー不要 |
| 機能スコープ(MVP) | 基本ブロック + スラッシュコマンド + 数式 | Notion 体験の 8 割を最小コストで実現 |
| エディタエンジン | Tiptap(ProseMirror 系) | 完全な WYSIWYG。低レベル制御が確保でき、将来の vim 層に必要 |
| vim keybind | Phase 2 で「有限サブセット」を実装 | 完全移植は無謀だがサブセットは状態機械として設計可能。MVP 時点でキー入力の一元インターセプト層(KeyRouter)だけ用意しておく |
| 数式 | MVP に含める(KaTeX) | `@tiptap/extension-mathematics` で実装コストが小さい |

## アーキテクチャ

Manifest V3 拡張 + コンテンツスクリプト直接マウント方式。

```
file:///path/to/note.md を開く
        │
        ▼
Chrome が素のテキストを <pre> に表示(これが初期データ源)
        │
        ▼ コンテンツスクリプト(*.md の file:// URL にマッチ)が起動
        │   1. <pre> から生 Markdown を取得(読み取りに許可ダイアログ不要)
        │   2. ページ DOM を丸ごとエディタ UI に差し替え(React + Tiptap をマウント)
        ▼
   編集(WYSIWYG)
        │
        ▼ Cmd+S
   Tiptap ドキュメント → Markdown へシリアライズ → Prettier で整形
        │
        ▼
   File System Access API で上書き
   ・初回のみ: showSaveFilePicker(ファイル名は URL から自動プリセット)で同じファイルを選択
   ・以降そのタブでは無音で上書き保存
```

設計上のポイント:

- **読み込みに許可不要。** Chrome が `file://` の `.md` を `<pre>` に表示するため、
  コンテンツスクリプトがそれを拾えば初期内容が手に入る。許可が要るのは初回保存の 1 回のみ。
- **iframe を使わずページに直接マウント。** 拡張ページの iframe 埋め込みは
  File System Access API の権限委譲で問題が出るため採らない。
- **状態はタブのメモリ内のみ。** ファイルハンドルはタブを閉じれば消える。
  `.md` 以外の永続状態(IndexedDB・localStorage 等)は持たない。
  タブを開き直したら保存時に再度 1 回だけピッカーが出る。
- **初回セットアップ:** ユーザーは `chrome://extensions` で本拡張の
  「ファイルの URL へのアクセスを許可する」を手動で ON にする(Chrome の仕様)。
- 未保存の変更があるタブを閉じようとしたら `beforeunload` で警告。

## モジュール構成

互いにインターフェースだけで繋がる 5 つの独立ユニット。

| ユニット | 責務 | 依存 |
|---|---|---|
| ① content | `<pre>` から Markdown 抽出、エディタのマウント | ②〜⑤を起動 |
| ② editor | Tiptap 設定、スラッシュコマンド、UI(React) | ③④⑤ |
| ③ keymap(KeyRouter) | 全キー入力の一元インターセプト。MVP では素通し+ショートカット振り分けのみ。Phase 2 で vim 状態機械がここに差し込まれる | なし(純粋) |
| ④ markdown | parse: md → Tiptap ドキュメント / serialize: 逆変換 / Prettier 整形。「md 文字列 in → md 文字列 out」の純関数 | なし(純粋) |
| ⑤ file(FileController) | ファイルハンドル保持、Cmd+S、未保存インジケータ、beforeunload 警告 | なし |

## エディタ機能(MVP)

対応ブロック・記法:

- 見出し(1〜3)、箇条書き、番号リスト、チェックボックス、引用、コードブロック
- 太字・斜体・取り消し線・インラインコード・リンク
- 数式: インライン `$…$` / ブロック `$$…$$`(KaTeX 同梱、オフライン動作)。
  クリックで LaTeX ソース編集、カーソルが離れるとレンダリングに戻る

ショートカット:

- `Cmd+B` 太字 / `Cmd+I` 斜体 / `Cmd+E` インラインコード / `Cmd+Shift+X` 取り消し線
- `Cmd+K` リンク / `Cmd+Alt+1〜3` 見出し / `Cmd+S` 保存

入力オートフォーマット(行頭で入力すると自動変換):

- `# ` → 見出し、`- ` → 箇条書き、`1. ` → 番号リスト、`[] ` → チェックボックス
- `> ` → 引用、``` ``` ``` → コードブロック、`$$` → 数式ブロック

スラッシュコマンド:

- `/` でフィルタ可能なブロックメニュー(見出し・リスト・コード・引用・数式など)。
  矢印キーと Enter で選択。

## Markdown 変換(品質の要)

- 対応記法は **GFM + 数式**。テーブルは MVP では編集対象外
  (既存ファイル内のテーブルは下記「生 Markdown ブロック」として表示・保持され、壊れない)。
- **YAML フロントマター**は編集対象にせず、文書先頭の折りたたみ生テキストブロックとして
  保持し、保存時にそのまま書き戻す。
- **未対応記法(生 HTML ブロック等)**は「生 Markdown ブロック」ノードとして
  そのまま往復させる。変換できないものを黙って消さない、が原則。
- 保存時: シリアライズ → Prettier(markdown パーサ、同梱)で整形 → 書き込み。
  箇条書き記号は `-`、見出しは `#`(ATX)スタイルに統一。

## エラー処理(原則: ユーザーの Markdown を絶対に失わない)

- 保存ピッカーのキャンセル: 未保存状態を維持して通知。何も壊れない。
- 書き込み権限の失効(NotAllowedError): 再度ピッカーを出して取得し直す。
- 外部変更の検知: 初回保存以降はハンドル経由で更新日時を確認できるため、
  他アプリによる変更を検知したら上書き前に警告する。
- dirty でなければ `Cmd+S` は何もしない(開いただけのファイルに整形差分を作らない)。
- パースで扱えない内容は「生 Markdown ブロック」として保持。黙って消えるルートを作らない。
- 文字コードは UTF-8 前提(制約)。

## テスト戦略

- **Markdown I/O ゴールデンテスト(最重要・Vitest):**
  フィクスチャ `.md` → parse → serialize → 期待値比較。
  加えて冪等性テスト `format(format(x)) === format(x)` を全フィクスチャに適用
  (2 回保存しても差分が出ないことを保証)。
- **ユニットテスト:** スラッシュメニューのフィルタリング、KeyRouter
  (Phase 2 では vim 状態機械を純粋関数としてテスト)。
- **手動スモークチェックリスト:** ファイルピッカーと `file://` 権限は
  ブラウザ自動化と相性が悪いため、「開く→編集→保存→再度開く」の手動手順を
  ドキュメント化して E2E の代替とする。

## プロジェクト構成

Vite + @crxjs/vite-plugin + React + TypeScript。

```
numenumd/
├── manifest.config.ts     # MV3 マニフェスト
├── src/
│   ├── content/           # ① <pre> 抽出 → エディタマウント
│   ├── editor/            # ② Tiptap 設定・スラッシュコマンド・UI
│   ├── keymap/            # ③ KeyRouter(将来ここに vim/ が入る)
│   ├── markdown/          # ④ parse / serialize / Prettier 整形
│   └── file/              # ⑤ FileController(保存管理)
└── tests/
    └── fixtures/          # ゴールデンテスト用 .md
```

## フェーズ計画

- **MVP:** 本ドキュメントの全機能(基本ブロック + スラッシュコマンド + 数式 + 保存整形)
- **Phase 2:** vim サブセット — モーダル状態(normal / insert / visual)、`hjkl`、
  `w b e`、`0 $ gg G`、`f t`、オペレータ `d c y` + カウント、テキストオブジェクト
  `iw i" ip`、`dd yy p`、`u`。KeyRouter に差し込む独立状態機械として実装し、
  「行 → ブロック」の写像(`dd` = ブロック削除、`j/k` = ブロック間移動)を採る。
- **Phase 3 候補:** テーブル編集、ブロックのドラッグ&ドロップ(⠿ ハンドル)、
  相対パス画像の表示(フォルダ単位の許可取得が別途必要)。

## スコープ外(明示)

- ネイティブメッセージングホスト(ヘルパーアプリ)
- 複数ファイルの横断管理・ファイルツリー・最近使ったファイル一覧
- クラウド同期・共同編集
- `.md` 以外のファイル形式
