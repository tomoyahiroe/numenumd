# MTG: 保存ハンドルの永続化(リロード後のピッカー再表示をなくす)

日付: 2026-08-09

## 前提(事前合意)

- リロードのたびに保存先を選び直す現状の体験を改善する。
- そのために **「永続状態を持たない」原則を破ってよい**(利便性を優先する、
  というユーザーの判断)。

## 調査済みの事実

headless Chrome + CDP で実測(2026-08-09):

- `file://` ページでも IndexedDB は開ける。
- 全ての `file://` ページで**同一のストアを共有**する(別ディレクトリの
  ページが親の書き込みを読めた)。
- Chrome プロセスの再起動をまたいで残る。
- `location.origin` は `"file://"`、`window.origin` は `"null"`(opaque)。

Chrome 122 以降、IndexedDB に保存した `FileSystemHandle` を取り出して
`requestPermission()` を呼ぶと、ファイルピッカーではなく三択の許可プロンプト
(今回のみ / 毎回許可 / 許可しない)が出る。許可はオリジン単位。
`file://` が opaque origin であるため「毎回許可」が実際に永続するかは
実機の許可 UI がないと未確認。

## 決定

- 覚えるのは**保存に成功したファイルだけ**(= 書き込み権限を得たハンドル)。
  ファイルパスをキーに `FileSystemFileHandle` を IndexedDB へ保存する。
  件数の上限は設けない。どのファイルに戻ってもピッカーが出ないほうが利便性が
  高いため。
- 許可が復帰しなかったときは、黙って従来のピッカーへフォールバックする。
  `Cmd+S` の時点でまず記憶したハンドルの許可を求め、断られたらピッカーを出し、
  そこで選ばれたハンドルで記憶を上書きする。
- プライバシー文書は「収集・送信しない」という主張を維持したまま、保存の項だけ
  「どのファイルを開いたかを端末内にのみ記録する」に書き換える(`PRIVACY.md` の
  「永続的な状態を持ちません」、`docs/store-listing.md` の「状態はブラウザの
  タブと .md ファイルの中にしかありません」が対象)。
- 記録を消す手段を用意する。~~使用頻度が低く本文の邪魔になるため、ヘッダではなく
  拡張のオプションページに「記憶した保存先を全部消す」を置く。~~
  **(2026-08-10 撤回・差し替え)** IndexedDB はオリジン単位で、保存先の記憶は
  `file://` オリジンのストアに入る。オプションページは `chrome-extension://`
  オリジンで動くためそれが見えず、この決定は技術的に成立しない。代わりに
  **エディタ側**(`.md` を開いている画面)に消去 UI を置く。オプションページから
  開いているタブへメッセージを中継する案は「消したいときに `.md` タブが開いて
  いないと消せない」という最悪の性質があるため採らない。
- ハンドルと一緒に**最終保存時の更新日時(mtime)も保存する**。現状はリロード後の
  初回保存で外部変更を検知できていない(`lastSavedMtime` が null のため conflict
  チェックを飛ばす)ので、あわせて直す。

- 原則の文言を緩める。`CLAUDE.md` の「永続状態を持たない」を
  「**保存先の記憶以外の**永続状態を持たない」にする。なし崩しを避けるため、
  例外を1つだけ明示する形にする。spec も同様に更新する。

## 保留

- `file://` は opaque origin(`window.origin === "null"`)なので、Chrome の
  「毎回許可」が本当に永続するかは実機の許可 UI がないと未確認。効かなかった
  場合は保存のたびに許可ダイアログが出る(それでもファイルピッカーで選び直す
  よりは良い)。実装時に実機で確認する。
- ファイルが移動・削除・リネームされたときの孤児レコードの掃除。件数上限を
  設けない決定と関係する。実装時に方針を決める。
