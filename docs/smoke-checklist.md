# 手動スモークチェックリスト

numenumd(ローカル `.md` を Notion 風 WYSIWYG で編集する Chrome 拡張)のリリース前に、
実機の Chrome で以下の項目を手動確認する。CI(`npm test` / `npm run lint` /
`npm run typecheck` / `npm run build`)はコードレベルの回帰しか検出できないため、
「実際の Chrome file:// ページ上でのユーザー体験」はこのチェックリストで別途担保する。

## 準備

1. `npm run build` で `dist/` を生成する。
2. `chrome://extensions` を開き、右上の「デベロッパーモード」を ON にする。
3. 「パッケージ化されていない拡張機能を読み込む」から `dist/` を選択する。
4. 読み込んだ numenumd の「詳細」を開き、「ファイルの URL へのアクセスを許可する」を ON にする
   (OFF のままだと `file://` 上で content script が一切動かない)。
5. 動作確認用に適当な `.md` ファイルと、`.md` 以外のファイル(例: `.txt`)を用意しておく。

## 1. 拡張読み込み + file URL アクセス許可で `.md` がエディタ表示になる

1. 準備済みの `.md` ファイルを Chrome で `file:///path/to/xxx.md` として開く。
2. Chrome 既定のプレーンテキスト表示(`<pre>` 一枚)ではなく、numenumd の WYSIWYG
   エディタ(ヘッダーにファイル名、本文が装飾された見た目)に置き換わることを確認する。
3. タブタイトルがファイル名になっていることを確認する。

## 2. `.md` 以外の file:// ページは乗っ取らない

1. 準備済みの `.txt`(または `.html` など `.md` 以外)ファイルを `file://` で開く。
2. Chrome 既定の表示のままで、numenumd のエディタに置き換わらないことを確認する。

## 3. 入力オートフォーマットが効く

空の段落で以下をそれぞれ入力し、対応するブロックに自動変換されることを確認する
(入力後にスペースまたは Enter を押すタイミングで変換される)。

- `# ` → 見出し1、`## `〜`###### ` → 見出し2〜6
- `- ` → 箇条書きリスト
- `1. ` → 番号付きリスト
- `[] ` → 未チェックの ToDo、`[x] ` → チェック済み ToDo
- `> ` → 引用
- ` ``` ` → コードブロック
- 空段落で `$$` とだけ入力して Enter、または `$$ `(スペース込み)→ 数式ブロック

## 4. キーボードショートカットが効く

選択範囲またはカーソル位置に対して以下が効くことを確認する。

- `Cmd+B` 太字 / `Cmd+I` 斜体 / `Cmd+E` インラインコード
- `Cmd+Shift+X` 取り消し線(`Cmd+Shift+S` も可。前者は `extensions.ts` の
  `StrikeExtraKeymap` による追加バインド、後者は Tiptap `Strike` 拡張の既定
  キーマップで、どちらもトグルとして効く。保存の `Cmd+S` とは別物)
- `Cmd+K` リンク(選択範囲がある状態で押すと URL 入力プロンプトが出る。空文字で
  確定するとリンク解除)
- `Cmd+Alt+1`〜`Cmd+Alt+6` で見出しレベル1〜6にトグル
- `Cmd+S` 保存(項目9・11・12で詳細確認)

## 5. `/` メニューが出る・絞り込める・Enter で挿入される

1. 空の段落で `/` を入力し、10項目(Heading 1 / Heading 2 / Heading 3 /
   Bulleted list / Numbered list / To-do list / Quote / Code block / Table /
   Math block)のメニューが出ることを確認する。
2. `/見出し` のように日本語キーワードを続けて入力すると、見出し系(Heading 1〜3)
   に絞り込まれることを確認する(`箇条書き`→Bulleted list、`番号`→Numbered list、
   `チェック`→To-do list、`引用`→Quote、`コード`→Code block、`数式`→Math block、
   `テーブル`→Table でも同様)。
3. `ArrowUp`/`ArrowDown` で選択項目が移動し、`Enter` で選択中の項目が挿入される
   ことを確認する。
4. マッチ0件(例: `/zzz`)のとき「No results」が表示され、その状態で `Enter` を
   押してもメニューが閉じるだけで改行や文字が残らないことを確認する。

## 6. 数式が KaTeX レンダリングされ、クリック編集できる

1. 地の文に `$x^2 + y^2 = z^2$` のようなインライン数式を含む段落を作り、KaTeX で
   数式としてレンダリングされることを確認する。カーソルをその中に置いて編集できる
   ことも確認する。
2. `$5 and $10` のように対になっていない `$` を含む文は数式として誤認されず、
   ただのテキストとして表示されることを確認する(Pandoc 方式のペア判定)。
3. `/` メニューの Math block、または空段落での `$$` 入力でブロック数式を作り、
   KaTeX でブロックレンダリングされることを確認する。
4. レンダリングされた数式(インライン/ブロックとも)をクリックすると編集用の
   生 LaTeX 表示に切り替わり、編集後にフォーカスを外す(blur)と再度レンダリング
   表示に戻ることを確認する。

## 7. テーブルが WYSIWYG で編集でき、保存しても壊れない

1. パイプテーブルを含む `.md` を開き、罫線付きの表として描画されることを確認する
   (揃え指定 `:---:` がある列は、その揃えで表示されること)。
2. セルをクリックしてカーソルを置くと、表の右端と下端に `+` ボタン、上端と左端に
   グリップ帯が現れることを確認する。表の外にカーソルを移すと消えること。
3. `+` ボタンで列と行がそれぞれ増えることを確認する。
4. 上端のグリップをクリックするとその列が選択され、`Backspace` で列ごと消えること。
   左端のグリップと行についても同様であることを確認する。
5. `Tab` で次のセルへ移動し、最終セルで `Tab` を押すと行が増えることを確認する。
6. セル内で `Shift+Enter` を押しても改行が入らないことを確認する
   (GFM のセルは改行を表現できないため、意図的に無効化している)。
7. `/table` で 3x3 の表が挿入できることを確認する。
8. 編集して `Cmd+S` で保存し、保存後のファイルが正しいパイプテーブルになっている
   ことと、もう一度開いて保存しても差分が出ない(冪等)ことを確認する。

## 7b. 変換できない表・生ブロックが verbatim 保全される

1. **ヘッダの列数より多いセルを持つ行**を含む表(例: ヘッダ2列に対し
   `| 1 | 2 | 3 |` の行)を含む `.md` を開き、その表が WYSIWYG 変換されず、
   黄色破線枠の生 Markdown ブロック(rawBlock)として表示されることを確認する。
2. そのブロックをクリックすると編集用テキストエリアに切り替わることを確認する
   (生 HTML ブロック・HTML テーブル・リンク参照定義 `[id]: url` を含む `.md`
   でも同様に rawBlock として保全されることを確認する)。
3. 何も変更せず `Cmd+S` で保存し、保存後のファイルで**超過セルが消えていない**
   ことを確認する。なお生ブロックの中身も保存時に Prettier の整形は通るため
   (`| 1 | 2 | 3 |` → `| 1   | 2   | 3   |` のような桁揃えは起きる)、
   バイト単位で不変なのは整形済みの記述だけである。保証しているのは
   「内容が落ちないこと」であって「1バイトも動かないこと」ではない。

## 8. frontmatter 入り md が折りたたみ表示され、保存後も verbatim

1. 先頭に `---` 区切りの YAML frontmatter を持つ `.md` を開き、`<details>` の
   折りたたみ UI(サマリ「Front matter」)として表示されることを確認する。
2. 開閉できること、クリックで編集用テキストエリアに切り替わることを確認する。
3. frontmatter 部分を変更せずに本文だけ編集して保存し、保存後のファイルの
   frontmatter 部分が元の記述のまま(インデントや空行も含め verbatim)であることを
   確認する(Prettier の markdown 整形はボディにのみ適用され、frontmatter には
   適用されない)。

## 9. 初回 `Cmd+S` でピッカー(ファイル名プリセット済み)→ 2回目以降は無音保存

1. `.md` を開いて何か編集し、初めて `Cmd+S` を押す。
2. OS のファイル保存ピッカーが開き、ファイル名にすでに現在のファイル名が
   プリセットされていることを確認する。
3. 同じ場所に保存を確定し、「保存しました」のトースト表示が出ることを確認する。
4. 続けて別の編集をして再度 `Cmd+S` を押し、ピッカーが出ずに無音(トーストのみ)で
   保存されることを確認する。

## 10. 保存された md が Prettier 整形済みで、再保存しても差分ゼロ(冪等)

1. 項目9で保存したファイルをテキストエディタで開き、Prettier(`proseWrap: preserve`)
   で整形された Markdown になっていることを確認する。
2. numenumd でそのファイルを開き直し、何も編集せず(dirty にせず)保存しようとしても
   何も起きない(項目11で確認)。強制的に軽微な編集(スペース1つ追加して削除等)をして
   保存し直し、保存前後でファイル内容に差分が出ない(冪等)ことを確認する。

## 11. 未編集のまま `Cmd+S` → 何も起きない。未保存でタブを閉じる → 警告

1. `.md` を開いた直後、何も編集せずに `Cmd+S` を押す。ピッカーもトーストも出ず、
   何も起きないことを確認する(`dirty` でないため保存処理がスキップされる)。
2. 何か編集して未保存のままタブを閉じようとすると、ブラウザの離脱確認ダイアログが
   出ることを確認する。
3. エディタ本体の外(ヘッダー領域などフォーカスが外れた状態)でも `Cmd+S` が
   正しく横取りされ、Chrome 既定の「ページを保存」ダイアログが開かないことも
   合わせて確認する。

## 12. エディタ表示中に他アプリでファイル変更 → `Cmd+S` で競合警告

1. numenumd で `.md` を開いて一度保存し(ファイルハンドルを確立させる)、さらに
   エディタ上で編集を続けて dirty な状態にする。
2. numenumd を閉じずに、別のテキストエディタ(VS Code 等)で同じファイルを開いて
   内容を変更し、保存する。
3. numenumd 側に戻って `Cmd+S` を押すと、「ファイルが他のアプリで変更されています。
   上書きしますか?」という確認ダイアログが出ることを確認する。
4. キャンセルすると「保存をキャンセルしました」のトーストが出て、ファイルは
   外部変更後の内容のまま(numenumd の内容では上書きされない)ことを確認する。
5. 再度 `Cmd+S` → 今度は確認ダイアログで OK を選び、numenumd 側の内容で
   上書きされ「保存しました」のトーストが出ることを確認する。
