# numenumd 設計ドキュメント

日付: 2026-08-01
ステータス: 承認待ち

## 概要

ローカルの Markdown ファイルを Notion ライクな WYSIWYG UI で編集できる Chrome 拡張機能。
`file:///…/*.md` をブラウザで開くと、そのページがエディタに置き換わる。保存時には
Markdown が Prettier で整形されて元ファイルに上書きされる。編集内容が `.md` ファイルの
外に残ることはなく、永続化するのは「どのファイルをどこへ保存したか」の記憶だけ
(下記「保存先の記憶」節)。

## 決定事項(経緯付き)

| 論点              | 決定                                            | 理由                                                                                                                      |
| ----------------- | ----------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| エディタの入口    | `file:///*.md` を開いたら拡張がページを乗っ取る | 「ファイルをブラウザで開く」動線に馴染む                                                                                  |
| ファイル書き戻し  | File System Access API(初回保存時のみピッカー)  | 拡張単体で完結。ネイティブヘルパー不要                                                                                    |
| 機能スコープ(MVP) | 基本ブロック + スラッシュコマンド + 数式        | Notion 体験の 8 割を最小コストで実現                                                                                      |
| エディタエンジン  | Tiptap(ProseMirror 系)                          | 完全な WYSIWYG。低レベル制御が確保でき、将来の vim 層に必要                                                               |
| vim keybind       | Phase 2 で「有限サブセット」を実装              | 完全移植は無謀だがサブセットは状態機械として設計可能。MVP 時点でキー入力の一元インターセプト層(KeyRouter)だけ用意しておく |
| 数式              | MVP に含める(KaTeX)                             | `@tiptap/extension-mathematics` で実装コストが小さい                                                                      |

## アーキテクチャ

Manifest V3 拡張 + コンテンツスクリプト直接マウント方式。

```
file:///path/to/note.md を開く
        │
        ▼
Chrome が素のテキストを <pre> に表示(これが初期データ源)
        │
        ▼ コンテンツスクリプト(*.md の file:// URL にマッチ)が起動
        │   1. <pre> から生 Markdown を取得(読み取りに許可ダイアログ不要)
        │   2. ページ DOM を丸ごとエディタ UI に差し替え(React + Tiptap をマウント)
        ▼
   編集(WYSIWYG)
        │
        ▼ Cmd+S
   Tiptap ドキュメント → Markdown へシリアライズ → Prettier で整形
        │
        ▼
   File System Access API で上書き
   ・記憶済み: IndexedDB のハンドルで許可を求め、通れば無音で上書き
   ・未記憶/許可が通らない: showSaveFilePicker(ファイル名は URL から自動プリセット)
   ・以降そのタブでは無音で上書き保存
```

設計上のポイント:

- **読み込みに許可不要。** Chrome が `file://` の `.md` を `<pre>` に表示するため、
  コンテンツスクリプトがそれを拾えば初期内容が手に入る。許可が要るのは初回保存の 1 回のみ。
- **iframe を使わずページに直接マウント。** 拡張ページの iframe 埋め込みは
  File System Access API の権限委譲で問題が出るため採らない。
- **編集内容はタブのメモリ内のみ。** 本文が `.md` ファイルの外に残ることはない。
  ただし**保存先の記憶だけは例外**として IndexedDB に永続化する
  (下記「保存先の記憶」節。経緯は `docs/mtg/2026-08-09-save-handle-persistence.md`)。
- **初回セットアップ:** ユーザーは `chrome://extensions` で本拡張の
  「ファイルの URL へのアクセスを許可する」を手動で ON にする(Chrome の仕様)。
- 未保存の変更があるタブを閉じようとしたら `beforeunload` で警告。

## モジュール構成

互いにインターフェースだけで繋がる 5 つの独立ユニット。

| ユニット               | 責務                                                                                                                   | 依存       |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------- | ---------- |
| ① content              | `<pre>` から Markdown 抽出、エディタのマウント                                                                         | ②〜⑤を起動 |
| ② editor               | Tiptap 設定、スラッシュコマンド、UI(React)                                                                             | ③④⑤        |
| ③ keymap(KeyRouter)    | 全キー入力の一元インターセプト。MVP では素通し+ショートカット振り分けのみ。Phase 2 で vim 状態機械がここに差し込まれる | なし(純粋) |
| ④ markdown             | parse: md → Tiptap ドキュメント / serialize: 逆変換 / Prettier 整形。「md 文字列 in → md 文字列 out」の純関数          | なし(純粋) |
| ⑤ file(FileController) | ファイルハンドル保持、Cmd+S、未保存インジケータ、beforeunload 警告                                                     | なし       |

## エディタ機能(MVP)

対応ブロック・記法:

- 見出し(1〜3)、箇条書き、番号リスト、チェックボックス、引用、コードブロック
- 太字・斜体・取り消し線・インラインコード・リンク
- 数式: インライン `$…$` / ブロック `$$…$$`(KaTeX 同梱、オフライン動作)。
  クリックで LaTeX ソース編集、カーソルが離れるとレンダリングに戻る

ショートカット:

- `Cmd+B` 太字 / `Cmd+I` 斜体 / `Cmd+E` インラインコード / `Cmd+Shift+X` 取り消し線
- `Cmd+K` リンク / `Cmd+Alt+1〜3` 見出し / `Cmd+S` 保存

入力オートフォーマット(行頭で入力すると自動変換):

- `# ` → 見出し、`- ` → 箇条書き、`1. ` → 番号リスト、`[] ` → チェックボックス
- `> ` → 引用、` ``` ` → コードブロック、`$$` → 数式ブロック

スラッシュコマンド:

- `/` でフィルタ可能なブロックメニュー(見出し・リスト・コード・引用・数式など)。
  矢印キーと Enter で選択。

## Markdown 変換(品質の要)

- 対応記法は **GFM + 数式**。
- **YAML フロントマター**は編集対象にせず、文書先頭の折りたたみ生テキストブロックとして
  保持し、保存時にそのまま書き戻す。
- **未対応記法(生 HTML ブロック等)**は「生 Markdown ブロック」ノードとして
  そのまま往復させる。変換できないものを黙って消さない、が原則。
- 保存時: シリアライズ → Prettier(markdown パーサ、同梱)で整形 → 書き込み。
  箇条書き記号は `-`、見出しは `#`(ATX)スタイルに統一。

### テーブル(GFM パイプテーブル)

決定の経緯は `docs/mtg/2026-08-09-markdown-table.md` を参照。

- **編集可能にする表の線引きは「情報が落ちるかどうか」だけで決める**(ハイブリッド)。
  GFM はヘッダ列数を超えたセルを黙って捨てる仕様のため、そういう行を1行でも
  含む表は従来どおり「生 Markdown ブロック」として verbatim 保全する。それ以外の
  表は編集可能な table ノードへ変換する。セル数が足りない行の空セル補完は許容する。
- 判定に使うセル分割ロジックは markdown-it の `escapedSplit` と同一のものを
  1ファイル(`src/markdown/table-cells.ts`)に置き、パース側の判定とシリアライズ側の
  `|` エスケープが**同じ実装を共有**する(`math-spans.ts` と同じ方針。検出規則が
  食い違うと往復が壊れるため)。
- **揃え記法**(`:---` / `:---:` / `---:`)は列の属性として往復で保持する。
- **セル結合は提供しない。** GFM のパイプテーブルにセル結合の記法自体が存在しない
  ため、`mergeCells` を UI に出さない。HTML テーブルの `rowspan` / `colspan` は
  従来どおり「生 Markdown ブロック」として生のまま表示・保存される。
- **セルの中身は単一段落に制限する。** GFM のセルにはインラインしか書けないので、
  リスト・コードブロック・複数段落を作れてしまうと保存時に必ず壊れる。同じ理由で
  セル内の Shift+Enter(強制改行)も無効にする。
- 保存時の桁揃えは既存の Prettier 整形に任せる。シリアライザは最小形(`| a | b |`)を
  出力すればよい。
- **編集 UI:** 表にカーソルがある間だけ右端と下端に `+` ボタンを出して行/列を追加する。
  上端と左端のグリップ帯をクリックするとその行/列を選択(`CellSelection`)し、
  選択中の Backspace で削除する。Tab でセル移動、最終セルの Tab で行追加。
  スラッシュコマンド `/table` で 3x3(ヘッダ行あり)を挿入する。

## 保存先の記憶(numenumd 自身が持つ唯一の永続データ)

決定の経緯は `docs/mtg/2026-08-09-save-handle-persistence.md` を参照。

MVP は「永続状態を一切持たない」方針だったため、タブをリロードするたびに保存先を
選び直す必要があった。利便性を優先してこの原則を**1点だけ**緩める。

- **覚えるのは保存に成功したファイルだけ**(= 書き込み権限を得たハンドル)。
  ファイルパスをキーに `FileSystemFileHandle` と最終保存時刻を IndexedDB へ置く。
  件数の上限は設けない。
- `file://` ページでも IndexedDB は使え、全ての `file://` ページで同一ストアを
  共有し、ブラウザの再起動もまたぐ(headless Chrome + CDP で実測済み)。
- 保存時はまず記憶したハンドルの許可を求める(Chrome 122 以降、ファイル
  ピッカーではなく三択の許可プロンプトが出る)。**断られたら黙って従来の
  ピッカーへフォールバック**し、そこで選ばれたハンドルで記憶を上書きする。
- 最終保存時刻も一緒に持つことで、リロード後の初回保存でも外部変更を検知できる
  ようになる(従来は `lastSavedMtime` が null で conflict チェックを飛ばしていた)。
- 記録は**ユーザーが消せる**。消去 UI はエディタ側(`.md` を開いている画面)に
  置く。IndexedDB はオリジン単位で、記憶は `file://` オリジンのストアに入るため、
  `chrome-extension://` オリジンで動くオプションページからは触れない。
- 記録するのは保存先だけで、**本文は一切保存しない**。外部送信も行わない。
- 「唯一」は _numenumd 自身が読み書きするデータ_ の話。ブラウザ側にはこれとは
  別に、ピッカーの最終ディレクトリ(`showSaveFilePicker({ id })`、
  `picker-id.ts` 参照)と File System Access の許可が残りうる。
- `file://` のストアは**全ての `file://` ページで共有される**(実測済み)。
  ローカルで開いた別の HTML から保存先のパス一覧を読めてしまうため、この事実は
  `PRIVACY.md` に明記する。

## エラー処理(原則: ユーザーの Markdown を絶対に失わない)

- 保存ピッカーのキャンセル: 未保存状態を維持して通知。何も壊れない。
- 書き込み権限の失効(NotAllowedError): 再度ピッカーを出して取得し直す。
- 外部変更の検知: 初回保存以降はハンドル経由で更新日時を確認できるため、
  他アプリによる変更を検知したら上書き前に警告する。
- dirty でなければ `Cmd+S` は何もしない(開いただけのファイルに整形差分を作らない)。
- パースで扱えない内容は「生 Markdown ブロック」として保持。黙って消えるルートを作らない。
- 文字コードは UTF-8 前提(制約)。

## テスト戦略

- **Markdown I/O ゴールデンテスト(最重要・Vitest):**
  フィクスチャ `.md` → parse → serialize → 期待値比較。
  加えて冪等性テスト `format(format(x)) === format(x)` を全フィクスチャに適用
  (2 回保存しても差分が出ないことを保証)。
- **ユニットテスト:** スラッシュメニューのフィルタリング、KeyRouter
  (Phase 2 では vim 状態機械を純粋関数としてテスト)。
- **手動スモークチェックリスト:** ファイルピッカーと `file://` 権限は
  ブラウザ自動化と相性が悪いため、「開く→編集→保存→再度開く」の手動手順を
  ドキュメント化して E2E の代替とする。

## プロジェクト構成

Vite + @crxjs/vite-plugin + React + TypeScript。

```
numenumd/
├── manifest.config.ts     # MV3 マニフェスト
├── src/
│   ├── content/           # ① <pre> 抽出 → エディタマウント
│   ├── editor/            # ② Tiptap 設定・スラッシュコマンド・UI
│   ├── keymap/            # ③ KeyRouter(将来ここに vim/ が入る)
│   ├── markdown/          # ④ parse / serialize / Prettier 整形
│   └── file/              # ⑤ FileController(保存管理)
└── tests/
    └── fixtures/          # ゴールデンテスト用 .md
```

## 開発ハーネス

### pre-commit(husky + lint-staged)

- ステージされたファイルに ESLint(--fix)+ Prettier を適用。
- `tsc --noEmit`(型チェック)+ `vitest run`(全テスト)をパスしないとコミット不可。

### PR 自動 CI(GitHub Actions)

- `pull_request` トリガーで lint / typecheck / test / build(拡張の zip を
  アーティファクト化)の 4 ジョブ。
- main ブランチは保護設定: 直接 push 禁止・CI グリーン必須・PR 経由のみ。

### Chrome Web Store 自動デプロイ(CD)

- リリースタグ(`v*`)の push をトリガーに build → zip → Chrome Web Store API で
  アップロード&公開。
- マージ毎ではなくタグ毎にする理由: ストア公開は取り消しが効きにくく審査も挟まるため、
  「マージ = 開発の前進」「タグ = 意図したリリース」を分離する。
- デプロイ前にタグと `manifest.json` のバージョン一致をチェック。
- **Secrets 未設定時はデプロイジョブを自動スキップ**する(ワークフロー自体は先に整備)。
  CWS デベロッパーアカウント取得後に以下を行えば有効化される:
  1. Chrome Web Store デベロッパー登録(登録料 $5)
  2. 初回のみ手動アップロードで拡張 ID を取得
  3. GitHub Secrets に `CLIENT_ID` / `CLIENT_SECRET` / `REFRESH_TOKEN` / `EXTENSION_ID` を登録

### マージゲート(独立 subagent レビュー)

- PR をマージする前に、実装セッションの文脈を共有しない新規 subagent にレビューを依頼する
  ルールを `CLAUDE.md` に明文化する。subagent は PR ブランチをチェックアウトし、
  スペック・実装計画との整合、テストの実在性(テストが本当に検証しているか)、
  diff の品質を独立に確認する。
- マージ条件: **CI グリーン + 独立レビュー承認**の両方。承認後に `gh pr merge`。
- 狙いは、実装セッション自身が「自分の作ったものを自分で承認」するのを防ぐこと。

## フェーズ計画

- **MVP:** 本ドキュメントの全機能(基本ブロック + スラッシュコマンド + 数式 + 保存整形)
- **Phase 2:** vim サブセット — モーダル状態(normal / insert / visual)、`hjkl`、
  `w b e`、`0 $ gg G`、`f t`、オペレータ `d c y` + カウント、テキストオブジェクト
  `iw i" ip`、`dd yy p`、`u`。KeyRouter に差し込む独立状態機械として実装し、
  「行 → ブロック」の写像(`dd` = ブロック削除、`j/k` = ブロック間移動)を採る。
- **テーブル編集(0.3.0):** 上記「テーブル(GFM パイプテーブル)」節のとおり実装。
  MVP では編集対象外(生 Markdown ブロック扱い)だったものを Phase 3 候補から
  引き上げた。
- **Phase 3 候補:** ブロックのドラッグ&ドロップ(⠿ ハンドル)、
  相対パス画像の表示(フォルダ単位の許可取得が別途必要)。

## スコープ外(明示)

- ネイティブメッセージングホスト(ヘルパーアプリ)
- 複数ファイルの横断管理・ファイルツリー・最近使ったファイル一覧
- クラウド同期・共同編集
- `.md` 以外のファイル形式
